# เฟสงาน AUDRIX RELAY

ที่มาของการตัดสินใจ: [pc-audio-plan.md](pc-audio-plan.md)

เฟสจบแล้วให้เปลี่ยนสถานะเป็น `done` แล้วเติมวันกับหลักฐานหนึ่งบรรทัด (คำสั่งที่รัน หรือ commit). อย่าย้ายเฟสไปไฟล์อื่น.

สถานะมีสามคำ: `todo`, `blocked`, `done`.

## 0. ล็อกโปรโตคอลของเรา

- สถานะ: `done`
- เสร็จเมื่อ: 2026-10-11
- หลักฐาน: `recv` ได้ packets 50, lost 0, sample_rate 48000, peak 2449 จาก `send` ไป `127.0.0.1:40123`

แอปมือถือเป็นของเรา. ไม่ตรวจ APK คนอื่น.

UDP พอร์ต `40123`. ทุกฟิลด์เป็น little-endian.

```text
u32 sequence
u32 sample_rate
u16 channels
i16 samples[]
```

`send` ที่ไม่มีอาร์กิวเมนต์ส่งไป `127.0.0.1`. `send <ip>` ส่งไปที่นั้นพอร์ตเดิม. ไม่มีช่องเวอร์ชันในแพ็กเก็ต.

## 1. จับเสียงบน Windows

- สถานะ: `done`
- เสร็จเมื่อ: 2026-10-11
- หลักฐาน: `cargo run` พิมพ์ Headphones (High Definition Audio Device), sample rate 48000, channels 2, buffer 1056 frames, frames_read 1920

โปรแกรม Rust ตัวเดียว จับ WASAPI loopback แล้วพิมพ์ sample rate, channels และ buffer จากอุปกรณ์จริงบน Windows 11.

ยังไม่ส่งเน็ต. ยังไม่มี GUI. ยังไม่แยกหลาย crate.

## 2. ส่ง PCM16 ในเครื่องเดียวกัน

- สถานะ: `done`
- เสร็จเมื่อ: 2026-10-11
- หลักฐาน: `audrix-relay.exe recv` ได้ packets 50, lost 0, peak 2927 จาก `audrix-relay.exe send` บน 127.0.0.1:40123

ผู้ส่งส่งเฟรม PCM16 ทาง UDP พร้อม sequence number. ผู้รับบนเครื่องเดียวกันนับแพ็กเก็ตที่หาย.

เสร็จเมื่อเสียงที่จับได้เดินทางครบรอบนี้โดยยังไม่แตะมือถือ. ตัวรับนี้ยังใช้เทสในเครื่อง และต้องแก้ให้เข้ากับหัวแพ็กเก็ตในเฟส 0.

## 3. แอป Android ของเรา

- สถานะ: `todo`
- เสร็จเมื่อ: —
- หลักฐาน: บิลด์ `android/` ผ่านแล้ว. ยังไม่ได้เล่นบนมือถือจริง
- เริ่มได้เมื่อเฟส 0 เป็น `done` และมี Android SDK กับมือถือจริง

PC เปิดแล้วแสดง IP ของตัวเอง และรับเสียงระบบต่อได้ตอนย่อหน้าต่าง. มือถือใส่ IP นั้นแล้วกดเชื่อมต่อ. แอปมือถือเล่นต่อได้ตอนย่อแอป ผ่านบริการเบื้องหลัง.

เสร็จเมื่อมือถือจริงใน Wi-Fi วงเดียวกันเล่นเสียงจาก PC ได้โดยไม่มีอินเทอร์เน็ต. อีมูเลเตอร์ไม่นับ.

การทดสอบ 30 นาทียังไม่นับในรอบแรก.

## 4. วัดและบีบอัด

- สถานะ: `todo`
- เสร็จเมื่อ: —
- หลักฐาน: —
- เริ่มได้เมื่อเฟส 3 เป็น `done`

ใส่ Opus, jitter buffer และเชื่อมใหม่เมื่อหลุด. จด CPU, RAM, latency และ packet loss ของ PCM16 เทียบกับ Opus จาก release build.

เป้า latency ของรุ่นแรกคือต่ำกว่า 100 ms. ยังไม่ลดไป 30–50 ms ในเฟสนี้. ทดสอบ Wi-Fi ที่มีสัญญาณรบกวนอยู่ในเฟสนี้.
